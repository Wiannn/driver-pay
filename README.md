# 司机工资结算系统

一款零依赖、单文件的司机工资结算工具。双击即可打开，数据存在浏览器本地（localStorage），支持云端扩展。

## ✨ 已实现功能

### 司机管理
- 司机信息增删改查（姓名、车牌、手机号必填 11 位校验）
- 手机号输入错误即时提示

### 路线与公里
- **两套独立分组**
  - 进目的地：固定三组（外一外二系 / 外四外五系 / 洋山系），可改名，不可增删
  - 提 / 还目的地：独立一套（超外系 / 外一外二系 / 外四外五系 / 外内系 / 洋山系），可自由新增、改名、删除
- **基础公里表自动查表**：始发地 → 各目的地的单段公里数
- **公里跟随分组**：组内地点没单独登记公里（或登记为 0）时，自动取所在分组的基准 —— 外一外二系按外一/外二、外四外五系按外四/外五、洋山系按洋山/沧海路。例如 创元六 在外四外五系，新库→创元六 直接按外四算 50
- **分组公里**：分组标题右侧「公里」按钮可给本组单独设一个公里（如「新库130」组设 130），组内全部地点跟随；东库自动按「洋山系 / 超外系 +10、其余 −10」推导，也可手动覆盖。目的地标签上会显示当前生效的公里数
- **同区域去重**：连续步骤同区域不加第二段公里（进外一 → 提东森只算外一的公里）
- **自动算总公里**：搭完始发地+步骤，公里自动累加
- **公里留白**：目的地属于既无基准、也没设分组公里、自己又没登记的分组时，总公里留空由手工填写
- **路线库模板**：常用路线存成模板，趟次录入直接选
- **直接搭建**：临时路线不用存路线库，趟次录入时直接搭

### 提成自动规则
| 步骤组合 | 自动提成 |
|---------|---------|
| 纯进 1 段（外系） | 10 |
| 纯进 1 段（洋山系） | 0 |
| 纯提 / 纯还 / 纯落 1 段（外系） | 10 |
| 纯提 / 纯还 / 纯落 1 段（洋山系） | 100 |
| 进 + 提 / 进 + 还 / 进 + 落（外系） | 30 |
| 进 + 提 / 进 + 还 / 进 + 落（洋山系） | 100 |
| 一进二提（还可与落混用，都是外系） | 60 |

步骤动作有四种：**进**、**提**、**还**、**落**。「提」「还」「落」共用同一份目的地列表，提成规则也完全一致。

公里和提成都可手动覆盖自动值。

### 趟次录入
- 月份筛选 + 司机筛选
- 分页：每页固定 12 条，支持「跳至 X 页」直接跳转；切换月份/司机自动回第一页
- 两种模式：选模板 / 直接搭建（随时切）
- **箱号列**：双击编辑，仅允许字母数字，自动转大写
- **备注列**：双击编辑，支持任意文字
- 所有数据冗余存路线快照（route_origin + route_steps + route_name），历史不受模板变更影响

### 出勤登记
- 月历视图，点击格子循环切换状态：正常 → 休息 → 台风 → 清空
- 颜色区分状态：🟦 正常 / 🟧 休息 / 🟥 台风
- 鼠标悬停显示日期、状态、当日趟次数
- 顶部统计：正常 X 天 / 休息 X 天 / 台风 X 天 / 趟次记录 X 天（对照）

### 加油录入
- 按月份 + 司机筛选
- 加油日期、加油量（升）、单价、总金额、备注

### 结算与导出
- 按月份生成每位司机的工资结算卡
- 自动算：上班天数（优先取出勤登记）、总公里、总提成、总加油、实发工资
- 一键导出 Excel（xlsx）
- 导出内容含：结算汇总（上班/休息/台风天数）、出勤明细、趟次明细、加油明细、全司机汇总

### 地图（需高德 Key）
- 「地图」页按区域上色显示所有始发地 / 目的地
- **搜索**：地图页搜索框同时搜「我的地点」（已保存的始发地/目的地，输入即筛选，不耗配额）和「地图上的位置」（高德 POI，按搜索键才查）。选「我的地点」里有坐标的直接定位放大，没坐标的进入点选
- 分组勾选过滤；右侧地点列表按区域分组（始发地 / 外一外二系 / 外四外五系 / 洋山系 / 未分组），每组可点标题折叠收起，标题右侧显示「已标注数/总数」
- 三种方式标注坐标：地点标签上的 📍 按钮、右键地点选「在地图上点选」后点地图、右键选「用弹窗精确设置」
- 左侧点击地点行只会定位放大并弹出地点名，不会进入选点状态；选点必须主动从右键菜单进入，避免误触
- **右键菜单**：右键地点列表 / 目的地标签 / 地图上的圆点，可「用弹窗精确设置」「在地图上点选」「清除坐标」
- 未配置 Key 时地图页显示申请指引，其余功能不受影响

### 备份恢复
- 按钮在「月度结算」页右上角：导出备份 / 恢复备份
- 导出 JSON 备份文件（包含全部数据，含坐标）
- 恢复备份会覆盖当前全部数据，建议定期导出

## 🚀 使用方式

### GitHub Pages 在线使用
打开：https://wiannn.github.io/driver-pay/

**注意**：每个人打开自己的浏览器用自己的数据，因为 localStorage 只存在本地，多人之间不共享。

### 本地开发
```bash
# 安装依赖（首次）
npm install

# 开发模式，热更新，改完浏览器自动刷新
npm run dev
# 然后浏览器打开 http://localhost:5173

# 生产构建，输出单文件 HTML 到 dist/
npm run build
```

> 如果给高德 Key 设置了**域名白名单**，把 `localhost` 和 `127.0.0.1` 也加进去，否则本地 dev 模式地图加载不出来。

### 自动部署
`main` 分支有新 push 时，GitHub Actions 自动执行 `npm ci → npm run build → 部署 dist/`，1 分钟内刷新在线页面。无需手动操作。

## 📁 项目文件

### 构建配置
| 文件 | 说明 |
|------|------|
| `vite.config.js` | Vite 配置：`root: src/`、`base: ./`（适配 GitHub Pages 子路径） |
| `package.json` | npm 脚本：`dev`（热更新）、`build`（Vite 构建 + inline 内联） |
| `scripts/inline.js` | Vite build 后运行：从 `src/` 按顺序合并 11 个 JS + 把 Vite 压缩的 CSS 内联 → `dist/index.html` 单文件 |
| `.github/workflows/deploy.yml` | push main 自动构建部署到 GitHub Pages |
| `.gitignore` | 排除 `node_modules/`、`dist/` |

### 源码（`src/`）
| 文件 | 说明 |
|------|------|
| `src/index.html` | 页面骨架：顶栏、导航、各页空 section、按顺序引入 css/js |
| `src/css/base.css` | 全局变量、顶栏、按钮、toast |
| `src/css/pages.css` | 多页共用样式：录入表单、表格卡片、空状态等 |
| `src/js/core.js` | 常量（工资规则、高德 Key）、工具函数、localStorage 存储与迁移、公里/提成计算规则 |
| `src/js/data.js` | 数据增删改查（addTrip / removeDriver 等） |
| `src/js/pages.js` | definePage / mountPages 页面挂载框架 |
| `src/js/init.js` | 初始化、月份切换、页面切换（最后加载） |
| `src/pages/settlement.js` | 月度结算页（含 Excel 导出、数据备份） |
| `src/pages/trips.js` | 趟次录入页（分页、双模式搭建、行内编辑） |
| `src/pages/fuel.js` | 加油录入页 |
| `src/pages/attendance.js` | 出勤登记页 |
| `src/pages/map.js` | 地图页（高德） |
| `src/pages/drivers.js` | 司机信息页 |
| `src/pages/routes.js` | 线路价目页（含始发地 / 进港区 / 提还堆场管理弹窗） |

> 拆分规则：所有 js 共用一个全局作用域，普通 `<script>` 按顺序加载。
> 页面代码「一页一文件」：每个 `src/pages/页面.js` 用 `definePage('页面id', { html, css, init })` 定义自己的结构、样式和事件，骨架里只留一个空的 `<section class="page" id="page-xxx">`。
> 新增页面：新建 `src/pages/页面.js`，在 `src/index.html` 里加空 section 和一行 `<script src="./pages/页面.js">`（放在 `js/init.js` 之前），然后 `npm run dev` 即可预览。

## 🔧 管理目的地/始发地/基础公里

页面「线路价目」页 → 顶部按钮：
- **管理始发地**：增删行驶起点
- **管理进目的地**：增删进段目的地；分组固定三组（外一外二系 / 外四外五系 / 洋山系），组内可拖拽，组可改名，不能增删
- **管理提空箱目的地**：增删提 / 还目的地；分组独立一套，可新增、改名、删除

**拖拽分组**：把目的地标签拖到对应区域卡片里即可，组内自动按名称排序。

**分组增删改**（提 / 还目的地）
- 底部「＋ 新增分组」→ 输入名称 → 确定（新组自动分配一个地图颜色）
- 分组标题右侧 **✎** → 直接改成输入框，回车保存、Esc 取消
- 分组标题右侧 **×** → 删除分组（组内地点自动落到「未分组」，地点本身不删）
- 改动即时保存，并同步地图页的筛选条、右侧地点列表、标记颜色与趟次/路线下拉

**基础公里表**在代码 `defaultDb()` 里的 `base_km` 对象，可在「管理始发地/目的地」时动态补齐，后续计划提供专门的基础公里表编辑弹窗。

## 🗺️ 地图 Key 申请步骤（3 分钟）

1. 打开 https://console.amap.com ，注册并完成实名认证（个人开发者免费）
2. 「应用管理」→「创建新应用」→ 名称随便填
3. 在该应用下「添加 Key」→ **服务平台选「Web端（JS API）」**
4. 复制生成的 **Key** 和 **安全密钥（jscode）**
5. 打开 `src/js/core.js`，搜索 `AMAP_KEY`，填写两行：
   ```javascript
   var AMAP_KEY = '你的 Key';
   var AMAP_SECURITY_CODE = '你的安全密钥';
   ```
6. 刷新网页 → 切到「地图」页

建议在控制台给 Key 配置 **域名白名单**（`wiannn.github.io`），防止被盗用配额。

## 🛠️ 技术栈

- 前端：纯原生 HTML + CSS + JavaScript，无任何第三方运行时依赖
- 数据存储：localStorage
- 构建：Vite 6（CSS 压缩）+ Node inline 脚本（JS 按顺序合并内联）→ 输出单文件 HTML（1 次 HTTP 请求，GitHub Pages 国内加载快）
- 部署：GitHub Actions 自动 workflow（push main → build → deploy）
